# Changelog

## Unreleased

- **Summary findings normalization**: `scripts/summarize.py` now normalizes issue severities (`"BLOCKER"`, `"Major"`) to lowercase so mixed-case severities are not downgraded or misranked in `SUMMARY.md` and `scripts/notify.py`, and coerces non-string `title`, `screen`, and `issues` fields in `findings.json` without crashing.
- **Android screen element filtering**: `scripts/android/screen.py` now parses signed UIAutomator `bounds` (avoiding phantom on-screen tap targets from negative off-screen coordinates), skips zero-size or off-screen elements, and collapses multiline labels onto one line.
- **NativeScript builds (beta)**: `scripts/build/detect.sh` detects NativeScript apps (`nativescript.config.*` or `@nativescript/core` / `tns-core-modules` in `package.json`), and `scripts/build/android.sh` and `scripts/build/ios.sh` build a debug APK (`ns build android`) and an iOS Simulator `.app` (`ns build ios`), forwarding `build_args` / `BUILD_ARGS`. Beta: the tests use a stand-in for `ns`, no real NativeScript app has been built with it yet.
- **Slow and flaky networks (Android)**: optional `network` field in an Android persona's `device` (`slow` or `flaky`). `scripts/android/run_agent.sh` sets the emulator's network before the app launches, with `adb emu network speed` and `adb emu network delay`: EDGE speed for both, EDGE latency for `slow`, replies 0.5 to 3 s late for `flaky`. The job log shows what the emulator applied, and the agent's prompt names the condition. Kenji uses `flaky`.
- **Color blindness filters**: optional `color_filter` field in a persona's `device` (`protanopia`, `deuteranopia` or `tritanopia`). `scripts/color_filter.py` applies the simulation matrix directly to screenshots in `screen.py` across Android, iOS and web (since SurfaceFlinger's display daltonizer does not affect `screencap`), and the agent's prompt names the filter. Felipe uses `deuteranopia`.
- **A credit line in what you share**: `SUMMARY.md`, the draft issues and the Slack or Discord message now end with one line, "Tested with mobile-agent-testers", with a link to this repository. `SUMMARY_CREDIT=0` removes it everywhere.
- **Share your work**: [docs/share.md](docs/share.md) lists the video and images you can reuse, a `tested with mobile-agent-testers` badge, starting points for a post and a showcase list. `CITATION.cff` adds GitHub's "Cite this repository" button.
- **Run summary to Slack or Discord (opt-in)**: with `SUMMARY_WEBHOOK_URL` set on your machine, `collect.sh` posts a short version of `SUMMARY.md` to that webhook: how many reports and distinct bugs, the top 5 by severity and which personas hit them. Slack or Discord is picked from the webhook host (`SUMMARY_WEBHOOK_KIND` overrides it). It runs after decryption, never in the workflow, and prints neither the URL nor the message. `scripts/notify.py` also runs on its own.
- **Findings to draft GitHub issues**: `python3 scripts/draft_issues.py runs/<id>` turns the distinct findings in `SUMMARY.md` into draft GitHub issues on your machine, with severity, affected personas, devices and local screenshot paths. Dry run is the default (no network call). `--create --repo OWNER/REPO` opens them with `gh issue create`, asking confirmation for each issue with the target repo shown, so findings are never posted to a public testers repo by mistake.
- **A clearer map**: the screens are read left to right in a grid that is legible from the start, instead of one tall column. A short help opens on the first visit. Testers are colored chips at the top left, and one click shows a single path. The legend fits in four symbols. With no screen selected, the side panel gives an overview (screens, testers, screens no tester reached, findings). On a screen, it shows the screenshots, the findings and the testers first, and folds the rest. Cards are named after the text their testers share, not a random device name. On a phone, the panel sits below the map.
- **Web platform**: a new `web` platform runs the same personas in a phone's browser, on any site or web app, with Playwright device profiles. iPhones run on WebKit and Android phones on Chromium, on `ubuntu-latest`, with no emulator and no build. New inputs `web_personas` (default `none`) and `web_url`, and four personas: `tom`, `amelie`, `lena` and `arjun`. The tools in `scripts/web/` (`screen.py`, `gesture.sh`, `type.py`) follow the phone tools, and `screen.py` also reports page errors, console errors, failed requests, blocked links and new tabs. `block_hosts`, `record_video` and the accessibility check work for the web too; on iPhones scroll and swipe are scripted, because Playwright has no touch input on WebKit beyond a tap. The web agent's file tools stay in the checkout: it reads there and writes only under `results/`, because a website is untrusted input that can reach the agent through page text and console errors. `url` opens only pages of the site under test, and every command to the browser needs a per-run key, so the site cannot drive it through `127.0.0.1`.
- **Android: the tools leave no file the app can see**: the screen dumps (`screen.py`, the map robot, the pass-through in front of `adb`, the state read after a replay) and the screen recordings are now written to `/data/local/tmp` on the phone, not to its shared storage. On LocalSend, an agent opened the file picker of the system and picked its own screen dump: a phone that only replays did not have that file, so the path stopped there. The recordings no longer show in the app's gallery either.
- **Replay: Back that closed the keyboard**: before each Back, the pass-through in front of `adb` asks the phone whether the keyboard is open. If it is, the trace writes `hideKeyboard` instead of Back, and Explore-Compile-Replay (pinned at `f89aa13`) replays it only while a keyboard is on the screen. After typing, the keyboard of a replay may already be closed, and Back then left the screen: 3 of the 43 paths of a run of the map robot on LocalSend stopped just after such a Back.

## 0.2.0 (25 November 2026)

Every screen of your app on one map with the paths of the testers, and paths that replay with no model (experimental, Android). Also new: reproduce a bug report, an improvement report, compare two versions, cheaper models.

- **Map: one card for one screen in other forms**: the same screen in another language, text size or device is now one card even when the app has no ids. It is grouped by its layout without the texts, and the first screen after a fresh start is one card for every tester. On a run of LocalSend in 10 languages, 50 cards became 20. What is left can be merged by hand on the screen's panel, or on demand by Claude with `scripts/merge_screens.py` (one call on your Claude login). Merges go to `trace.notes.json`, and Separate undoes them. See [docs/dashboard.md](docs/dashboard.md).
- **Keep an APK**: `keep-apk.yml`, started by hand, takes the APK an earlier run built (kept 3 days, encrypted), checks its SHA-256 and attaches it with the app's license files to a pre-release on an existing tag, so that later runs replay on the same bytes. Only for an open source app, since the APK becomes public. See [docs/replay.md](docs/replay.md#replay-kept-traces-many-times).
- **collect.sh calls no model by default**: grouping duplicate reports with Claude now needs `SUMMARY_GROUPING=1`, since it runs on your own Claude login. Without it, identical titles are merged. The summary is also written in UTF-8 on Windows, where it stopped on a title in Arabic or Turkish.
- **The online demo shows LocalSend**: the [online demo](https://pierridotite.github.io/mobile-agent-testers/) now opens the map of LocalSend, a real open-source app, made by the robot with no model (27 starts of the app) and one tester. It stays static: no model is called and no key is used. `scripts/demo_pack.py --name` sets the name shown on the page.
- **Replay: a tester who leaves the app and comes back**: when the agent opens the app again with adb (`monkey -p`, `am start`) after leaving it, the trace opens it again too (`launchApp`, its data kept), and the run page counts these returns. Before, the replay stayed on the home screen. See [docs/replay.md](docs/replay.md#replay-it-right-after-the-run).
- **Replay: why a step found nothing**: when a replay stops at a step or a check that looks for an element, its line says whether the keyboard was open, whether the element is on the screen and in what form, and what now stands where it was when the agent tapped it, never its name. See [docs/replay.md](docs/replay.md#replay-kept-traces-many-times).
- **Replay kept traces many times (experimental)**: with `replay_traces=<folder>`, no agent runs. The traces kept in `<folder>/<persona>/` are replayed `replay_times` times each (20 by default) on that persona's phone, with no model key in the job, the last time with the network of the tools closed. A public artifact keeps every result with no text of the app. Each replay that does not give what its trace recorded says where it stopped and what the phone showed then: the kind of window in front, whether the app was running, its start time, a window that stopped responding, a crash. Before each replay of a trace that asks for a fresh state, the harness stops the app and clears its data, since a replay could find the app where the one before it ended. `traces/demo-app/` holds two paths to try it for free. See [docs/replay.md](docs/replay.md#replay-kept-traces-many-times).
- **Map maker with no model (experimental)**: with `map=robot`, a robot maps the app's screens on Android with no model and no cost: it fills each form with test values, opens each control once and comes back, and never taps a control that deletes, pays or signs out. Each start of the app is a trace that replays with no model. With `map=robot+agent`, an agent is called only for the forms the robot could not pass. `gh workflow run map-check.yml` checks it on the demo app. See [docs/dashboard.md](docs/dashboard.md).
- **Replay: taps with no name of their own**: a name on several lines (a Flutter tab is `Send`, then `Tab 2 of 3`) is now a name the replay finds, kept with a space for each line break as Maestro matches it. A tap on something with no name inside an element that has one (an icon in a card) is replayed at the same place inside that element, not on its centre. An id that covers half of the screen or more is no longer used as a target, the tap is stored as a point: in a Flutter app it is the only id under the finger. The run page counts how the taps of a path are found again (by name, by id, by position). See [docs/replay.md](docs/replay.md).
- **Replay: emptied fields and swipes**: the trace now holds a field the agent empties (`type.py ""`, or the cursor to the end then deletes), replays the tap that opens a field before it is emptied where its text ends, because Maestro erases before the cursor, and keeps the two ends of a swipe. The replay line names the kinds of the three steps before a stop. The Replay check follows 44 steps, with a long text typed over, and replays the path as it was once written to show where it stopped. See [docs/replay.md](docs/replay.md).
- **Replay check**: a workflow started by hand follows a fixed path on Tiny Todo with the tools of an agent, writes the trace and replays it on an emulator, with no model and no secret (`gh workflow run replay-check.yml`). The trace now names each tap on the screen tree of that moment, also when the agent taps several times after one screenshot, counts elements that share a name the way Maestro does, and holds long presses, text typed with `adb shell input text` and several keys in one command.
- **Replay right after the run (experimental)**: with `replay_path=true`, the path of each Android tester is compiled by Explore-Compile-Replay and replayed with Maestro on the same phone once the agent is done, with no model and no model key in its environment. The run page says in one line whether it passed or at which step it stopped; the flow and the details join the encrypted results. A replay that stops never fails the run. The trace now names the model that explored. See [docs/replay.md](docs/replay.md).
- **Map of the app's screens (experimental)**: `python3 scripts/dashboard.py runs/<run id>` opens a page on your machine with a map of every screen of the app and the testers' paths on it: one colored lane per tester on each arrow, a heat map of real or estimated taps on each screen, the findings seen there, one tester's path at a time, each device in its own shape with its own heat map, comments per screen. A finding becomes a check in two clicks: pick the element on the screen, must be visible or not, known bug; the check goes to `trace.json` (only checks can change) and the compiled flow stays red until the bug is fixed. A map maker agent ([briefs/map.md](briefs/map.md)) first opens every screen once, so the map shows the screens no persona reached. Each path is a trace that Explore-Compile-Replay compiles to a Maestro flow. Nothing leaves your machine. See [docs/dashboard.md](docs/dashboard.md).
- **A replayable path for each Android tester (experimental)**: each run now writes `trace.json` next to the report, the taps the agent made stored by the name of the element, not by coordinates. [Explore-Compile-Replay](https://github.com/pierridotite/explore-compile-replay) compiles it to a Maestro flow that reruns with no model. The texts the agent typed are kept apart in `trace.params.json`. The agent's tools and brief do not change. See [docs/replay.md](docs/replay.md).
- **Increased contrast and reduced motion**: two optional persona switches. `increase_contrast` turns on Increase Contrast on iOS (`simctl ui`) and high contrast text on Android; `reduce_motion` turns on Reduce Motion on iOS. Android emulators already run with animations off. Both are set before the app starts, and the agent is told about them. Grace and Sven use them.
- **Shorter README**: the home page keeps what it does, the real runs, the quick start, contributing and the teams section. The FAQ, limits, how it works and the comparison with Maestro moved to [docs/faq.md](docs/faq.md), and every input with the supported frameworks to [docs/configuration.md](docs/configuration.md), in the five languages.
- **Contributing**: [CONTRIBUTING.md](CONTRIBUTING.md) and a section in the README with ideas where help is welcome (other agent CLIs like OpenCode, web apps, physical phones, new personas, findings to issues, other CI), where each one starts in the code and how to test it offline.
- **Build arguments**: the `build_args` input adds arguments to the automatic build of both platforms, like `--dart-define=API_URL=https://staging.example.com` for a Flutter app that needs its backend address (Gradle and xcodebuild arguments for the other frameworks). Keys go in a `BUILD_ARGS` secret, never printed ([scripts/build/args.sh](scripts/build/args.sh)).
- **How each agent ended, on the run page**: finished, out of turns, usage limit, refused token or key, no API credit, rate limit or overloaded API, as an annotation with what to do next, plus turns and cost in the job summary. Nothing the agent wrote is printed, since public logs are public. `collect.sh` prints the same line for each agent ([scripts/agent_status.py](scripts/agent_status.py)).
- **setup.sh**: asks again after an empty paste or a wrong choice, checks an API key with Anthropic before saving it (a free call, the key never on the command line), warns when a token does not look like one and when the repo is private, where macOS minutes count ten times. `setup.ps1` does the same, except the online check.
- **Feedback**: issue forms to share how a run went on your app, and three questions about a hosted version for teams.
- **Cheaper models**: `model=haiku`, or any Anthropic-compatible API (OpenRouter, DeepSeek, Kimi, GLM, MiniMax, Qwen) with the new `llm_base_url` input and an `LLM_API_KEY` secret ([scripts/llm_env.sh](scripts/llm_env.sh)). The findings depend on how well the model reads screenshots and reasons: [docs/cheaper-models.md](docs/cheaper-models.md).
- **Improvement report**: with [briefs/improve.md](briefs/improve.md), each persona uses the app once to reach its goal, then lists what to change first, by area and impact. SUMMARY.md starts with the goals reached, the actions and the scores, then the improvements.
- **Compare two versions**: `scripts/compare.py` puts two runs of the same personas side by side (two branches, two builds): goals reached, actions, scores, issues seen on one version only, improvements by area ([docs/compare-versions.md](docs/compare-versions.md)).
- **README**: shorter, with a "What it does" list of the uses and one table of the LocalSend, AnkiDroid and Flutter runs. Their screenshots, findings and commands moved to [docs/examples.md](docs/examples.md), in the five languages of the README.
- **Reproduce a bug report**: the `bug_report` input takes an issue (`owner/repo#123` or its URL) or the steps as text. Each agent follows it on its own device with [briefs/reproduce.md](briefs/reproduce.md) and answers yes, no or unclear, with screenshots; the summary starts with a table of the devices where it happens.
- **Standalone skill**: `skills/mobile-agent-testers/` is the plugin's setup skill as a plain Agent Skill, for skill catalogs and agents without Claude Code plugins. A test keeps the two copies identical.

## 0.1.0 (19 November 2026)

The first tagged version: everything behind the [LocalSend, AnkiDroid and Flutter runs](docs/runs/).

- **One workflow** builds your app (Flutter, React Native, Expo, native Kotlin and Swift, Kotlin Multiplatform, Capacitor, .NET MAUI) or downloads a prebuilt APK or .app, then gives each persona its own Android emulator or iOS Simulator on GitHub Actions.
- **20 ready-made personas**: 14 languages, right to left, tablets, Android 10 to 15, text from small to iOS's largest accessibility size. `all` runs them all, `none` skips a platform.
- **Accessibility check** on every screen the agents read: controls with no name and touch targets under 48 dp (Android) or 44 pt (iOS).
- **Encrypted results**: reports, screenshots, build logs and optional screen recordings (`record_video`) are encrypted with your public key before upload. Analytics hosts are blocked inside the phones.
- **One summary**: `scripts/collect.sh <run id>` decrypts everything and groups the reports that describe the same bug into `runs/<id>/SUMMARY.md`.
- **Tests** run offline on every push, on Python 3.9 and 3.13: accessibility check, persona matrix, `personas.json`, summary, and the encrypted results path from the runner to `collect.sh`.
- **Public app repos** need no token; private ones take a read-only `SOURCE_REPO_TOKEN`.
- **Claude Code plugin**: `/plugin marketplace add pierridotite/mobile-agent-testers` sets it up for your app.

Already made a copy from the template? Take `.github/workflows/agent-testers.yml`, `scripts/`, `AGENT_BRIEF.md` and `personas.json` from this version.
